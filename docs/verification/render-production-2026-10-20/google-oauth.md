# Google sign-in repair — October 20, 2026

Google sign-in reached Google's authorization page but failed with HTTP 400 `invalid_request`: **“Missing required parameter: client_id.”** The authorization request had an empty client ID. Read-only inspection confirmed that the production Clerk Google connection's custom client ID and client secret fields were blank.

The user created Google Cloud project `careiq-production-auth`, the **CareIQ** OAuth app with an **External** audience, and Web application client **CareIQ Production Web** with:

- Authorized JavaScript origin: `https://app.careiqlabs.com`
- Authorized redirect URI: `https://clerk.careiqlabs.com/v1/oauth_callback`

Clerk subsequently showed **Enabled**, and its saved credentials persisted after reload. A private comparison confirmed that the secret exactly matched Google's created secret. The client ID matched only after trimming **one trailing ASCII space** after `.apps.googleusercontent.com`. A fresh native Chrome attempt then failed with Google HTTP 401 `invalid_client`: **“The OAuth client was not found.”** This is an intermediate failure, distinct from the original missing-ID error.

The final correction was verified after another Clerk reload: the saved client ID exactly matches Google's created ID, contains no whitespace, and the connection remains **Enabled**. No credential values are recorded here.

A fresh native Chrome flow from CareIQ `/sign-in` → **Other sign-in options** → **Google** reached Google's account chooser without the previous 400/401 errors. Selecting the existing work Google account opened the normal **“Sign in to careiqlabs.com”** consent screen, requesting only name/profile picture and email. The owner completed Google consent. The return landed at `/sign-in#/sso-callback`, but CareIQ displayed its custom password form. Manually opening **Other sign-in options** mounted Clerk and immediately resumed the callback, advancing to `/session-tasks` with the required organization setup form. No organization was created.

CareIQ delegates Google authentication to Clerk's prebuilt components. The initial credential correction changed provider configuration. The separately reproduced callback rendering defect requires the web patch below. [Clerk setup](https://clerk.com/docs/guides/configure/auth-strategies/social-connections/google).

Keep scopes limited to `openid`, `https://www.googleapis.com/auth/userinfo.email`, and `https://www.googleapis.com/auth/userinfo.profile`. Google exempts these basic identity scopes from Testing's test-user allowlist, warning and seven-day authorization expiry. Audience publication and brand verification remain separate; publication does not fix an empty client ID. [Google scopes](https://developers.google.com/identity/protocols/oauth2/scopes#oauth2), [audience](https://support.google.com/cloud/answer/15549945?hl=en), [verification](https://support.google.com/cloud/answer/13463073?hl=en).
