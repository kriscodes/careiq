## Interface changes

- The shared CareIQ header contains the language picker, account menu and help in one desktop utility row. The provider avatar’s root is constrained so the authentication form’s full-width rule cannot expand it. At narrow widths, the logo uses its own line and all three utility controls share the next row. Labels, focus and touch targets remain usable in English and Spanish.
- Set your location access keeps one top Back action. Its static role explanation is neutral, associated help text rather than a blue status or a second navigation control. Invitation actions retain their existing behavior.
- Practice settings retains the same header during loading, success and error states. Its outer host no longer adds a second padding frame around the shared header. Done appears after the content. The page has one main landmark, white surfaces and blue primary hover states.
- Settings and onboarding share a concise native time-zone dropdown with familiar English/Spanish labels for U.S. zones, Arizona’s no-daylight-saving rule, Alaska/Aleutians, Hawaii and U.S. territories. UTC remains available. A valid saved or device non-U.S. zone stays selectable instead of being silently replaced. Location creation still submits the selected IANA value to existing validation.
- Address fields keep bounded manual entry and browser street-address autocomplete. No external address lookup is enabled by this change.

## Ownership transfer

A selected eligible active administrator is named in a warning that explains loss of owner controls. The current practice name must be typed exactly. The final action names the recipient; a checkbox alone cannot transfer ownership. Changing recipient, practice identity/name or recipient eligibility clears the confirmation. Pending submissions lock against duplicate clicks. Rejections keep the selected values for a deliberate retry; a confirmed success exits settings and refreshes effective authority. At 320px, long recipient names/email addresses wrap in the warning and final button. The native select keeps its current-value display within the form; the warning and button retain the full recipient text.

`POST /api/v1/practice/ownership` now requires `userId`, `practiceId`, `confirmationName` and `acknowledgedUserId`. The service checks strict shape/field bounds, the exact current database practice name/ID and matching recipient acknowledgement. Current owner authorization, active provider administrator eligibility, active enrollment and success-only auditing remain enforced. A stale name or recipient is rejected without a successful-transfer audit. Errors have useful English/Spanish messages.
